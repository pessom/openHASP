# ESP32-2432S028R ("Cheap Yellow Display") – performance build

[Русская версия](cyd-esp32-2432s028r.ru.md)

This fork contains a tuned build of openHASP for the Sunton **ESP32-2432S028R**
(2.8" 320x240 ILI9341 SPI display, XPT2046 resistive touch, ESP32-WROOM without PSRAM, 4 MB flash).
The goal is a responsive UI on a board with very little RAM: faster redraws, no stalls of the GUI loop
on slow WiFi/MQTT and quicker WiFi reconnects.

All optimizations are enabled only for the `esp32-2432s028r_4MB` environment through build flags.
Every new flag has a default that keeps the original openHASP behaviour, so other boards are not affected.

## Building

```bash
cp platformio_override-template.ini platformio_override.ini
# uncomment the line "user_setups/esp32/*.ini" in platformio_override.ini
pio run -e esp32-2432s028r_4MB
```

The firmware files are written to `build_output/firmware/`.
Flash the merged `*_full.bin` at address `0x0` for a fresh install or upload the `*.ota.bin` via the web UI.

### CI

`.github/workflows/build_cyd.yaml` builds `esp32-2432s028r_4MB` on every push to the
`cyd-2432s028r*` branches (changes to `*.md` are ignored) and can be started manually (*workflow_dispatch*).
The firmware is attached to the run as the `esp32-2432s028r_4MB` artifact.

## Build flags

Defined in `user_setups/esp32/esp32-2432s028.ini`, section `[env:esp32-2432s028r_4MB]`.

| Flag | Value | Default | Effect |
|------|-------|---------|--------|
| `LV_DISP_DEF_REFR_PERIOD` | `20` | `50` | LVGL redraw period, ms |
| `LV_INDEV_DEF_READ_PERIOD` | `10` | `20` | Touch read period, ms |
| `LV_VDB_SIZE` | `16384` | `32768` | Size of one draw buffer, bytes |
| `LV_VDB_DOUBLE` | `1` | `0` | Two DMA-capable draw buffers: LVGL renders the next area while the previous one is sent (same RAM as 1 x 32 kB) |
| `LV_COLOR_16_SWAP` | `1` | `0` | RGB565 in SPI byte order, the buffer is sent to the panel without copying |
| `HASP_USE_TFT_DMA` | `1` | `0` | Non-blocking flush to the TFT via DMA (LovyanGFX driver) |
| `HASP_LOOP_DELAY` | `1` | `2` | Delay at the end of the main loop, ms |
| `HASP_LOG_LEVEL` | `4` (WARNING) | `LOG_LEVEL_TRACE` | Trace/verbose logging is compiled out of the hot paths |
| `HASP_SERIAL_TX_BUFFER` | `1024` | not set | Serial TX buffer, logging does not wait for the UART |
| `HASP_MQTT_PUBLISH_TASK` | `1` | `0` | MQTT messages are published from a separate FreeRTOS task |
| `LVGL_FREETYPE_MAX_BYTES` | `16384` | `2048` | Total FreeType glyph cache, the 2 kB cache caused constant re-rendering |
| `HASP_WIFI_FAST_RECONNECT` | `1` | `0` | Fast WiFi reconnect, see below |
| `HASP_USE_FTP` / `HASP_USE_TELNET` | `0` | `1` | FTP and Telnet are disabled to free RAM, `SimpleFTPServer` is not linked |

`LV_COLOR_16_SWAP` and `LV_DISP_DEF_REFR_PERIOD` in `include/lv_conf_v7.h` can now be overridden from build flags.

## Details

### Display

* `src/hasp_gui.cpp` allocates two internal DMA-capable buffers when `LV_VDB_DOUBLE > 0`.
* `src/drv/tft/tft_driver_lovyangfx.cpp` keeps the SPI transaction open and returns right after starting
  `writePixelsDMA`. The next `setAddrWindow` waits for the previous transfer. With a single buffer the driver
  waits for the DMA before calling `lv_disp_flush_ready`, so the old behaviour is safe.
* Screenshots (file and HTTP) swap the bytes back to little-endian RGB565, so `.bmp` files are correct
  with `LV_COLOR_16_SWAP=1`.

### MQTT (`HASP_MQTT_PUBLISH_TASK`)

`esp_mqtt_client_publish` blocks until the data is written to the socket. `mqttPublish` now copies the topic
and payload into a queue of 32 messages that is handled by the `mqtt_pub` task (3 kB stack).
The GUI never waits for the network. When the queue is full the message is dropped and counted as failed.
Before disconnecting, `mqttStop` gives the task up to 0.5 s to send the queued messages, including the offline LWT.

Incoming message logging (`QUE ... =>`) was moved from WARNING to TRACE.

### WiFi (`HASP_WIFI_FAST_RECONNECT`)

* The channel and BSSID of the last successful connection are saved to NVS (namespace `wifi`, keys
  `fc_ssid`, `fc_chan`, `fc_bssid`). They are written only when the access point changes, to spare the flash.
* A reconnect first tries the known channel and BSSID (`WIFI_FAST_SCAN`). If that fails, the next attempt does
  a full channel scan.
* Failed attempts are retried after 5, 10, 20 and then every 30 s instead of a fixed 30 s.
  An attempt without a result is considered failed after 20 s.

### Page numbers

* `page 300` used to wrap around in `uint8_t` and open page 44. Values above 255 are now treated as invalid.
* For an invalid page number the plate publishes the current page, so the sender can resync.

### Build scripts

`tools/auto_firmware_version.py` and `tools/esp_merge_bin.py` use `importlib.metadata` instead of `pkg_resources`,
which is no longer shipped with recent setuptools. `esp_merge_bin.py` calls `esptool` with the PlatformIO Python
interpreter.

## Disabling an optimization

Remove or set the flag to `0` in `[env:esp32-2432s028r_4MB]`. For example, to get FTP and Telnet back,
remove the `HASP_USE_FTP=0` / `HASP_USE_TELNET=0` lines, the matching `build_unflags` lines and `SimpleFTPServer` from `lib_ignore`.
