# ESP32-2432S028R ("Cheap Yellow Display") – сборка с оптимизациями

[English version](cyd-esp32-2432s028r.md)

В этом форке есть настроенная сборка openHASP для Sunton **ESP32-2432S028R**
(дисплей 2.8" 320x240 ILI9341 по SPI, резистивный тач XPT2046, ESP32-WROOM без PSRAM, 4 МБ flash).
Цель — отзывчивый интерфейс на плате с очень малым объёмом RAM: быстрее перерисовка, GUI не зависает
на медленном WiFi/MQTT, WiFi быстрее переподключается.

Все оптимизации включаются только для окружения `esp32-2432s028r_4MB` через флаги сборки.
Значение по умолчанию у каждого нового флага сохраняет исходное поведение openHASP, другие платы не затронуты.

## Сборка

```bash
cp platformio_override-template.ini platformio_override.ini
# раскомментировать строку "user_setups/esp32/*.ini" в platformio_override.ini
pio run -e esp32-2432s028r_4MB
```

Файлы прошивки появятся в `build_output/firmware/`.
Для чистой установки прошивается объединённый `*_full.bin` по адресу `0x0`, для обновления — `*.ota.bin` через веб-интерфейс.

### CI

`.github/workflows/build_cyd.yaml` собирает `esp32-2432s028r_4MB` при каждом пуше в ветки
`cyd-2432s028r*` (изменения `*.md` игнорируются), также запускается вручную (*workflow_dispatch*).
Прошивка прикладывается к запуску как артефакт `esp32-2432s028r_4MB`.

## Флаги сборки

Заданы в `user_setups/esp32/esp32-2432s028.ini`, секция `[env:esp32-2432s028r_4MB]`.

| Флаг | Значение | По умолчанию | Назначение |
|------|----------|--------------|------------|
| `LV_DISP_DEF_REFR_PERIOD` | `20` | `50` | Период перерисовки LVGL, мс |
| `LV_INDEV_DEF_READ_PERIOD` | `10` | `20` | Период опроса тача, мс |
| `LV_VDB_SIZE` | `16384` | `32768` | Размер одного буфера отрисовки, байт |
| `LV_VDB_DOUBLE` | `1` | `0` | Два DMA-буфера: LVGL рисует следующую область, пока предыдущая передаётся (RAM как у 1 x 32 КБ) |
| `LV_COLOR_16_SWAP` | `1` | `0` | RGB565 в порядке байт SPI, буфер уходит в дисплей без копирования |
| `HASP_USE_TFT_DMA` | `1` | `0` | Неблокирующий вывод на TFT через DMA (драйвер LovyanGFX) |
| `HASP_LOOP_DELAY` | `1` | `2` | Пауза в конце главного цикла, мс |
| `HASP_LOG_LEVEL` | `4` (WARNING) | `LOG_LEVEL_TRACE` | Логи trace/verbose вырезаются из горячих участков |
| `HASP_SERIAL_TX_BUFFER` | `1024` | не задан | Буфер TX Serial, логирование не ждёт UART |
| `HASP_MQTT_PUBLISH_TASK` | `1` | `0` | Публикация MQTT из отдельной задачи FreeRTOS |
| `LVGL_FREETYPE_MAX_BYTES` | `16384` | `2048` | Общий кэш глифов FreeType, при 2 КБ глифы постоянно перерисовывались |
| `HASP_WIFI_FAST_RECONNECT` | `1` | `0` | Быстрое переподключение WiFi, см. ниже |
| `HASP_USE_FTP` / `HASP_USE_TELNET` | `0` | `1` | FTP и Telnet отключены ради RAM, `SimpleFTPServer` не линкуется |

`LV_COLOR_16_SWAP` и `LV_DISP_DEF_REFR_PERIOD` в `include/lv_conf_v7.h` теперь можно переопределить флагами сборки.

## Подробности

### Дисплей

* `src/hasp_gui.cpp` при `LV_VDB_DOUBLE > 0` выделяет два буфера во внутренней DMA-памяти.
* `src/drv/tft/tft_driver_lovyangfx.cpp` держит SPI-транзакцию открытой и возвращается сразу после запуска
  `writePixelsDMA`. Следующий `setAddrWindow` дожидается окончания передачи. С одним буфером драйвер
  ждёт DMA до вызова `lv_disp_flush_ready`, поэтому старый режим безопасен.
* Скриншоты (в файл и по HTTP) переставляют байты обратно в little-endian RGB565, `.bmp` корректны
  при `LV_COLOR_16_SWAP=1`.

### MQTT (`HASP_MQTT_PUBLISH_TASK`)

`esp_mqtt_client_publish` блокируется, пока данные не записаны в сокет. Теперь `mqttPublish` копирует топик
и payload в очередь на 32 сообщения, которую обрабатывает задача `mqtt_pub` (стек 3 КБ).
GUI никогда не ждёт сеть. При переполнении очереди сообщение отбрасывается и считается неотправленным.
Перед отключением `mqttStop` даёт задаче до 0,5 с на отправку очереди, включая offline LWT.

Лог входящих сообщений (`QUE ... =>`) переведён с WARNING на TRACE.

### WiFi (`HASP_WIFI_FAST_RECONNECT`)

* Канал и BSSID последнего успешного подключения сохраняются в NVS (namespace `wifi`, ключи
  `fc_ssid`, `fc_chan`, `fc_bssid`). Запись только при смене точки доступа, чтобы не изнашивать flash.
* Переподключение сначала идёт на известный канал и BSSID (`WIFI_FAST_SCAN`). Если не удалось, следующая
  попытка выполняет полное сканирование каналов.
* Повторы после неудачи — через 5, 10, 20 и далее каждые 30 с вместо фиксированных 30 с.
  Попытка без результата считается неудачной через 20 с.

### Номера страниц

* `page 300` раньше переполнял `uint8_t` и открывал страницу 44. Значения больше 255 теперь считаются неверными.
* На неверный номер страницы панель публикует текущую страницу, чтобы отправитель синхронизировался.

### Скрипты сборки

`tools/auto_firmware_version.py` и `tools/esp_merge_bin.py` используют `importlib.metadata` вместо `pkg_resources`,
которого нет в новых setuptools. `esp_merge_bin.py` вызывает `esptool` интерпретатором Python из PlatformIO.

## Как отключить оптимизацию

Удалить флаг или задать `0` в `[env:esp32-2432s028r_4MB]`. Например, чтобы вернуть FTP и Telnet,
удалить строки `HASP_USE_FTP=0` / `HASP_USE_TELNET=0`, соответствующие строки `build_unflags` и `SimpleFTPServer` из `lib_ignore`.
